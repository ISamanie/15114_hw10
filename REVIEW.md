# Workout Tracker code review

Reviewed the Expo SDK 58 app at commit `cebb71a` against the local `spec.md`. Of the 22 acceptance criteria, 17 pass in source or logic checks, 3 fail, and 2 require native verification. The app source was left unchanged.

`npm run lint`, `tsc --noEmit`, and Expo bundle exports for iOS and Android passed. Targeted Node checks exercised the catalog, search, set validation, volume, PRs, chart series, and workout edits and deletes. No native build, simulator, or physical device run was available. UI findings are based on source inspection.

## Additional findings

23. [FAIL] **A valid small decimal can prevent saving an edited workout.** The parser accepts `0.0000001` kg within the input’s length limit. The edit initializer formats the stored value as `1e-7`, which the same parser rejects. This was reproduced with the save and re-edit expressions. An unchanged set can block saving unrelated edits to the workout. `src/components/workout-block.tsx:38–42`, `src/app/workout-tracker.tsx:46–55`, `src/data/workouts.ts:121–130`, `src/data/workouts.ts:146–148`.
24. [WARN] **Android gallery selection has no activity-recreation recovery.** The modal only consumes the immediate result from `launchImageLibraryAsync`. If Android destroys `MainActivity` during the picker flow, the app never retrieves the pending selection. This is documented SDK behavior. The device scenario was untested here. `src/app/create-exercise.tsx:3`, `src/app/create-exercise.tsx:18–46`. [Expo SDK 58 ImagePicker documentation](https://docs.expo.dev/versions/v58.0.0/sdk/imagepicker/#imagepickergetpendingresultasync)
25. [WARN] **A malformed local snapshot can lock the user out.** Loading rejects malformed JSON and invalid top-level fields. The error screen only offers Try Again, which rereads the same snapshot. Validation also checks array containers without validating their records, so a malformed entry can pass hydration and fail later during filtering or rendering. The implementation retains the saved data on disk. `src/data/workout-store.tsx:21–35`, `src/data/workout-store.tsx:45–60`, `src/data/workout-store.tsx:77–80`, `src/app/_layout.tsx:11–21`, `src/data/workouts.ts:112–118`.
26. [WARN] **Viewing an exercise can rewrite the entire workout history.** A change to the five-entry recent list goes through the same queue as substantive saves and serializes exercises, sessions, blocks, and sets in full. The amount of work grows with historical data and shares the queue with Finish Workout. This is a code-level scaling concern. No device benchmark was run. `src/data/workout-store.tsx:63–73`, `src/data/workout-store.tsx:87–93`.
27. [WARN] **The history table mounts every row.** The detail screen maps the complete history into a horizontal `ScrollView` inside the page’s vertical `ScrollView`. Long histories increase the number of mounted native views on entry. The exercise library and tracker already use virtualized lists for their catalogs. `src/app/exercise/[id].tsx:56–76`, `src/components/tracker-ui.tsx:8–14`, `src/app/data.tsx:30–34`, `src/app/workout-tracker.tsx:172–182`.
28. [WARN] **Unused starter navigation duplicates the active navigation and theme concepts.** The root mounts the stack directly. Native and web `AppTabs` implementations still define Home and Exercise Data, and the web version retains the Expo Starter header. Their theme uses the separate `Colors` object while the workout routes use `Palette`. These modules add maintenance and lint surface without a route that mounts them. `src/app/_layout.tsx:23–31`, `src/components/app-tabs.tsx:6–30`, `src/components/app-tabs.web.tsx:18–32`, `src/components/app-tabs.web.tsx:53–62`, `src/constants/theme.ts:10–25`, `src/constants/theme.ts:67–74`.
29. [WARN] **The workout rules have no checked-in regression tests.** The repository scripts expose lint and launch commands and have no test command or test files. The review’s temporary checks exercised critical rules, including volume, mixed-unit PRs, and session replacement. Those checks do not run automatically for future changes. `package.json:41–48`, `src/data/workouts.ts:121–161`, `src/data/workouts.ts:170–240`.
30. [PASS] **Editing and deletion keep derived metrics consistent.** A workout replacement drops its old session-linked blocks and sets before adding the revised record. Deletion removes the same related records. The save queue publishes the new in-memory snapshot after the disk write succeeds, and the workout and exercise views derive totals from current records. Targeted checks confirmed updated totals and no orphaned sets. `src/data/workouts.ts:163–188`, `src/data/workout-store.tsx:63–73`, `src/data/workout-store.tsx:87–88`, `src/app/workout-review.tsx:23–36`, `src/app/index.tsx:120–134`.
